# Surprise characters: the /surprises page and surprises.json

<!-- Moved from CLAUDE.md on 2026-11-12 so it loads only when needed. Keep it current with the code it describes. -->

Read before changing `settings_page/surprises_page.py`, `surprises.js`, `utils/surprises.py`, `surprises.json` handling, or how `disney.py` picks a transition. The characters themselves: `docs/dev/CHARACTERS.md`.

- **Surprise characters** (`/surprises`, `settings_page/surprises_page.py`): its own file, `surprises.json` beside config.json (gitignored, so a pull or update never conflicts with it: `self_update` ignores untracked files and never runs `git clean`; a new one is made with config.json's owner and mode, not root's, via `save_config(..., like=)`; a rollback restores config.json only, not this file, which is safe because the reader is tolerant: unknown keys and characters are ignored and kept on save, a bad value warns and takes its default, a missing or unreadable file means all defaults, so code that changes later needs no migration; `utils/config.py:load_surprises`, a missing or bad file means defaults), holding only what was changed: `{enabled, characters: {name: {on: false, chance: percent, ride_chance: percent, rides: [ride names]}}}`. `surprise_settings` reads it at start-up; `disney.py` applies it where a roll picks a transition and in `_park_reveal`: a character that's off gets the plain wipe, not another character. The odds tables and their defaults are `utils/surprises.py`, which `disney.py` imports. `chance` is the share of all ride screens (any character can take one, 0 by default if the table has none), `ride_chance` the share on a character's own rides (10% for a character with none by default); blank is the default and the first can't total over 100%. `rides` is exactly the rides a character visits (full ride names, matched loosely like the usual pieces; `[]` is none; no key keeps the `RIDE_VISITORS` defaults; `disney._visitor_specs`). On the page each character's **Add** button opens a panel under its row with every park's rides side by side, the character's default rides (`form.default_rides`: the rides whose names hold the table's pieces) ticked; ticking exactly the defaults saves nothing, and a picker never opened (no `rides_set_<name>` field, or no ride list yet) leaves the saved rides alone. The pickers fill from `ride_names.json` (`settings_page/ride_names.py`, beside config.json and gitignored: the configured parks' attractions and shows (a meet is a `SHOW` in the feed) that have a STANDBY or BOARDING_GROUP queue in `/live`, even with no wait posted now, so a closed ride stays and parades and exhibits don't; a ride seen before stays while it's still a child of the park; refetched in the background daily or when `parks` changes, and when the file's `FORMAT` is older; kept so the hotspot has it offline; names cleaned by `parks/names.py:clean_ride_name`, the app's own); with no list yet the row names the default rides and the panel says so. **Export / Import** move a board's settings to another, one click each and no text boxes. Export copies every setting on the page, saved or not: the page's script posts its form to `/surprises/export` on load and a moment after each edit (`form.apply_surprises`, then `form.snapshot_surprises`, which spells out every character's on, both chances and rides, defaults included, so a copy is complete on its own; a default ride is named by the pieces of its name when the ride list lacks it, so an empty list always means none; nothing is saved), so the click can copy at once (a browser only lets a click copy while it's fresh); it copies through a hidden textarea, which works on the boards' plain http, then the clipboard API. Import reads the clipboard where the browser allows (a secure page), else the click waits for one Ctrl/Cmd+V (a paste event, which plain http allows); it checks the paste with `Accept: application/json` (a bad one says why and leaves the page and its unsaved edits alone), then posts it to `/surprises/import` (`form.import_surprises`, defined in `settings_page/surprise_form.py` and re-exported by `form.py`, in steps: `_parse_export`, `_import_characters` (each one through `_import_entry`, then `_drop_defaults`), then the shared `_chances_total_problem`; `apply_surprises` builds each character with `_character_entry`; only what the page itself would save is kept, and whatever is just a default is dropped, so a copy doesn't freeze numbers a later version may change; a character this version lacks is skipped and named, any problem refuses the lot), which draws the page filled from it, not saved until Save and restart. Rides on the page post with `rides_set_<name>` (value `saved` for saved rides, else `1`) so an imported page saves its rides without a picker being opened, and so none-at-all stays none even when the ride list holds none of a character's default rides. A test runs the page's script through `node --check`: the others only look for text in it, and one quote in the wrong place kills sorting, the pickers, the totals and Export. Column headings sort the table (the page's script is `surprises.js`, read by `surprises_page.py`). `SURPRISE_LOOKS` ties a character's extra looks to it, `SURPRISES_UNUSED` hides transitions no roll picks, and a test holds the page's list to `TRANSITIONS`. Its form saves through `form.apply_surprises` (unknown characters and keys are kept), then restarts the app. `force_surprise` (config.json) ignores it.
